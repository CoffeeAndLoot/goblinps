## Concerns (two deviations from the brief, both necessary to keep the gates actually green)

1. **`test/tools/test_make_art.py`, `TestPlan.test_every_dash_part_is_planned`
   was not in the brief's scope but broke anyway.** It asserted
   `{p.name for p in make_art.PARTS}` equals *exactly* the dash's thirteen
   names — a strict-equality convention, not a "these are present" check.
   Adding the sixteen planner parts to `PARTS` (exactly as the brief
   instructs) makes that assertion false by construction, independent of
   anything I chose. I changed it to `issuperset(...)`, i.e. "the dash parts
   are still there," which is what the test's name and docstring-free intent
   actually claims. I did not touch any other test's assertions. Worth a
   second look: if a future part list somehow drops a dash part, this test
   still catches it; it just no longer forbids *adding* other parts, which
   is now normal (plan 7 will add more).

2. **`.luacheckrc` needed a new exemption for `GoblinPS/Data/Art.lua`.** The
   file already exempts three other generated `Data/*.lua` files
   (`Places.lua`, `Nodes.lua`, `Flights.lua`) plus the hand-written
   `Crossings.lua` from the 120-column limit, because generated/tabular data
   rows can run long. `Art.lua` had never needed the exemption because no
   part name was long enough — until `planner-frame-wide` and
   `planner-frame-tall`, whose generated rows (with their texture-coordinate
   values and size comment) land at 129 and 127 columns. I added the same
   exemption for `Art.lua`, matching existing project convention exactly
   rather than inventing a new approach. I did not shorten the generator's
   row format, since that's the established pattern for this exact
   situation elsewhere in the file.

Neither change touches shipped behavior — both are test/lint-only, and both
were required for the brief's own stated gates ("Python tests pass",
"zero warnings") to actually hold rather than being asserted past a real
failure.
